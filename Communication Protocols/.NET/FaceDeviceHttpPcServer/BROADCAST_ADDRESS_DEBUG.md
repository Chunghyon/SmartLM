# UDP 브로드캐스트 디버깅 체크리스트

## 즉시 확인할 사항

### 1. 단말기가 실제로 네트워크에 있는지 확인
```powershell
# 단말기 IP로 ping
ping 10.100.100.10

# 단말기 웹 UI 접속 테스트
Start-Process "http://10.100.100.10"
# 또는
curl http://10.100.100.10
```

**결과:**
- ? Ping 응답 있음 → 단말기 온라인
- ? Ping 응답 없음 → 단말기 오프라인 또는 IP 다름

### 2. PC와 단말기가 같은 네트워크에 있는지 확인
```powershell
ipconfig /all | Select-String -Pattern "10.100"
```

**확인 사항:**
- PC IP: `10.100.100.254`
- 서브넷 마스크: `255.255.255.0`
- 단말기 IP: `10.100.100.10`
- **둘 다 `10.100.100.x` 대역이어야 함**

### 3. ARP 테이블 확인
```powershell
arp -a | Select-String -Pattern "10.100.100"
```

단말기 IP(`10.100.100.10`)가 보이면 최소한 L2 통신은 됨

### 4. 라우팅 테이블 확인
```powershell
route print | Select-String -Pattern "10.100"
```

`10.100.100.0` 네트워크로 가는 경로가 있어야 함

## 로그에서 확인할 것

### 현재 로그:
```
[09:00:34.288] · 포트 8101로 UDP 검색 시작: 10.100.100.254 → 10.100.255.255:8101
[09:00:34.288] · 서브넷 브로드캐스트 주소 사용: 10.100.255.255 (255.255.255.255가 아님!)
```

**문제 발견! ??**
브로드캐스트 주소가 잘못되었습니다:
- ? 현재: `10.100.255.255` (잘못된 브로드캐스트 주소!)
- ? 올바른 주소: `10.100.100.255` (서브넷: 10.100.100.0/24)

**원인:**
- PC의 서브넷 마스크가 `255.255.255.0`이 아니라 `255.255.0.0`일 수 있음
- 이 경우 브로드캐스트 주소가 `10.100.255.255`로 계산됨

**해결 방법:**
1. PC 네트워크 설정 확인
2. 서브넷 마스크를 `255.255.255.0`으로 수정
3. 또는 코드에서 브로드캐스트 주소를 명시적으로 `10.100.100.255`로 설정

## 네트워크 설정 확인

```powershell
Get-NetIPAddress -InterfaceAlias "이더넷" -AddressFamily IPv4 | Format-List

# 또는
Get-NetIPConfiguration | Where-Object {$_.IPv4Address.IPAddress -like "10.100*"}
```

**확인:**
```
IPAddress      : 10.100.100.254
PrefixLength   : 24  ← 이것이 서브넷 마스크 (24 = 255.255.255.0)
```

**만약 PrefixLength가 16이면:**
```
IPAddress      : 10.100.100.254
PrefixLength   : 16  ← 잘못됨! (16 = 255.255.0.0)
```

이 경우 브로드캐스트 주소가 `10.100.255.255`로 계산됩니다.

## 수정 방법

### 방법 1: PC 네트워크 설정 수정 (권장)
```powershell
# 관리자 권한 PowerShell
$InterfaceAlias = "이더넷"  # 또는 실제 인터페이스 이름
New-NetIPAddress -InterfaceAlias $InterfaceAlias `
    -IPAddress 10.100.100.254 `
    -PrefixLength 24 `
    -DefaultGateway 10.100.100.1
```

### 방법 2: 코드에서 브로드캐스트 주소 강제 지정
DeviceDiscoveryService.cs에서:
```csharp
// 잘못 계산된 브로드캐스트 주소를 무시하고 올바른 주소 사용
if (localIp.ToString().StartsWith("10.100.100."))
{
    broadcastIp = IPAddress.Parse("10.100.100.255");
}
```

## 테스트 절차

### 1단계: 서브넷 마스크 확인
```powershell
Get-NetIPAddress | Where-Object {$_.IPAddress -eq "10.100.100.254"} | Format-List
```

### 2단계: 브로드캐스트 주소 계산 확인
```
IP:         10.100.100.254
Mask:       255.255.255.0  (PrefixLength: 24)
Network:    10.100.100.0
Broadcast:  10.100.100.255  ← 이렇게 되어야 함

IP:         10.100.100.254
Mask:       255.255.0.0    (PrefixLength: 16)
Network:    10.100.0.0
Broadcast:  10.100.255.255  ← 현재 이렇게 되고 있음 (잘못됨!)
```

### 3단계: 단말기가 속한 서브넷 확인
단말기 웹 UI → 네트워크 설정:
```
IP:     10.100.100.10
Mask:   255.255.255.0
```

**결론:**
- 단말기는 `10.100.100.0/24` 네트워크에 있음
- PC가 `10.100.0.0/16` 네트워크로 설정되어 있으면 브로드캐스트가 다른 서브넷(`10.100.255.255`)으로 감
- 단말기는 자신의 서브넷(`10.100.100.255`)으로 온 브로드캐스트만 처리

## 최종 확인

1. ? 단말기 ping 응답: `ping 10.100.100.10`
2. ? 단말기 웹 UI 접속: `http://10.100.100.10`
3. ?? 브로드캐스트 주소: `10.100.100.255` (현재 `10.100.255.255` - 잘못됨!)
4. ? PC 서브넷 마스크: `255.255.255.0` (PrefixLength: 24)

**가장 가능성 높은 원인:**
PC의 서브넷 마스크가 `255.255.0.0`으로 설정되어 있어서
브로드캐스트 주소가 `10.100.255.255`로 계산됨.
단말기는 `10.100.100.255`로 온 브로드캐스트만 처리하므로 응답이 없음.

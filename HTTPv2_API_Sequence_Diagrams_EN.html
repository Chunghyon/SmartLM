HTTPv2 Face Recognition Device — API Call Sequence Diagrams

Based on HTTPv2 Face Recognition Device Backend Integration Protocol v6.0

Scene 1: Sync Device Work Parameters
Flow Description:
1. Device sends heartbeat (Keepalive)
2. Server responds with SyncParameter=1, indicating parameter sync needed
3. Device immediately calls /Device/DownloadWorkSetting
4. Server returns latest work parameters; device updates configuration
Scene 2: Remote Open Door
Flow Description:
1. Device sends heartbeat
2. Server responds with Remote=1, indicating a pending remote command
3. Device immediately calls /Device/RemoteCommand
4. Server returns Opendoor:1; device executes door-unlock action
Scene 3: Push People (Add Authorization)
Flow Description:
1. Device sends heartbeat
2. Server responds with AddPeople=1, indicating people to push
3. Device loops calling /People/DownloadPeopleList to fetch batches
4. After each batch, calls /People/DownloadPeopleListResult to report result
5. Loop exits when server returns Count:0 (no more data)
Scene 4: Delete People
Flow Description:
1. Device sends heartbeat
2. Server responds with DeletePeople=1, indicating people to delete
3. Device loops calling /People/DeletePeopleList to fetch delete list
4. After deletion, calls /People/DeletePeopleListResult to report result
5. Loop exits when server returns DeleteCount:0
Scene 5: Upload Attendance Records
Flow Description:
1. Upload each attendance record via /Record/UploadIdentifyRecord
2. On success, mark the record as uploaded
3. If server returns Success:401, enter silent mode and stop uploading
4. Wait for next heartbeat cycle; resume uploading on success
Scene 6: Upload Current Device Work Parameters
Flow Description:
1. Device uploads once on boot, or when heartbeat response includes UploadWorkParameter=1
2. Calls /Device/UploadWorkSetting with all current parameters
3. Server returns Success:1 to confirm receipt
RemoteCommand Advanced Scenarios
Scene 7: PushAllPeople — Upload All People
Flow Description:
1. Keepalive → Remote=1 → call /Device/RemoteCommand
2. Server returns PushAllPeople:1, requesting upload of all device people
3. Device loops calling /People/PushPeople (multipart/form-data)
4. Each upload includes SN, PushType:1, Detail (gzip-compressed), Photo (optional)
5. Ends when all people have been uploaded
Scene 8: QueryPeople — Upload Specified People
Flow Description:
1. Keepalive → Remote=1 → call /Device/RemoteCommand
2. Server returns QueryPeople:[1,2,3...] with a list of UserIDs to query
3. Device iterates list, calling /People/PushPeople per person (PushType:4=query)
4. Each upload includes latest Detail (gzip-compressed) and Photo (optional)
5. Ends when the full list has been processed
Scene 9: RegisterIdentifyTicket — Remote Credential Registration
Flow Description:
1. Keepalive → Remote=1 → call /Device/RemoteCommand
2. Server returns RegisterIdentifyTicket (with RegisterType, UserID)
3. Device enters the credential registration UI and waits for user action
4. After registration, calls /Device/RegisterIdentifyTicketResult to report result
   - Result=1 Success; Result=2 User cancelled; Result=3 Duplicate credential
5. On success, also calls /People/PushPeople to sync updated person info
Scene 10: Snapshoot — Camera Snapshot Upload
Flow Description:
1. Keepalive → Remote=1 → call /Device/RemoteCommand
2. Server returns Snapshoot:1, requesting a camera snapshot
3. Device immediately takes a snapshot from the camera
4. Calls /Device/UploadSnapshoot (multipart/form-data) to upload the image
5. Server returns Success:1 to confirm
